# RULES.md — Model Adjustment Rules
# Last updated: June 1, 2026 — v2.2

## RULE TIER STRUCTURE
Rules are classified by tier. See MODEL_CORE Section 0 for full hierarchy.
- **[T1]** = Tier 1 Hard Gate — auto-block, no override
- **[T2]** = Tier 2 Soft Gate — each failure downgrades one tier; two failures = block at Medium
- **[T3]** = Tier 3 Sizing Scalar — affects size, not log/no-log decision

---

## CORE BETTING RULES

1. Never bet Under when one team has elite offense vs struggling starter — take run line or TT instead
2. NRFI reliable with elite starters on **both** sides only — not just one ace
3. Always use pitcher's last 5 starts for true_xFIP calculation — never rely on season xFIP alone. Apply regression weights by pitcher type AND season depth. See MODEL_CORE Section 1.
4. Verified same-day starters mandatory — wrong pitcher errors invalidate entire analysis
5. Skip ATL -1.5 run line — take ML or TT instead (close games + extras too frequent)
6. TJS return pitchers often come back sharp — do not assume rustiness
7. YRFI only with specific 1st-inning pattern evidence — not just ERA. See MODEL_CORE Section 15.
8. K props require two-sided matchup analysis — see MODEL_CORE Section 10
9. Kalshi edge direction: YES = away team. Kalshi is the primary bet source and edge target. Edge = (model Poisson probability − Kalshi VF) × calibration factor. Pinnacle VF is a sanity check — it flags divergence but is never the edge target.
10. Pitcher prop bets require same-day starter confirmation — search "[pitcher] starting today" before logging **[T1]**
11. Same-day starter confirmation required for ALL prop bets (probable ≠ confirmed) **[T1]**
12. Team streak data is one signal among many — treat streak alone as noise. A team on a losing streak with strong underlying metrics (rolling R/G above season avg, barrel%, xOPS) facing a weak starter is a bounceback spot, not a fade. See MODEL_CORE Section 9 Bounceback/Regression Algorithm.
13. ATL TT Over requires specific game-day reason beyond "good offense" — weak starter, favorable park, wind out, or hot recent stretch
14. Pinnacle doubleheader line gaps >15% are likely data errors — verify manually before acting
15. Rain = postponement risk only — never use as scoring suppressor
16. K rate is primary input for total projection, not ERA — 9+ K/9 suppresses totals regardless of ERA
17. Elite starter (xFIP <3.00) on either side = lean Under on game total — BUT only if the opposing offense is average or below. If opposing offense is elite (top-5 R/G season ≥5.2, or rolling 15-game ≥5.5) AND opposing starter is below replacement (xERA >6.0), the Under lean is OVERRIDDEN. Log the Over or skip entirely. **[T1] gate on Under at High when this fires**
18. TT Over requires recent offensive form (last 7-game R/G) — cold offense + shaky pitcher does not automatically produce runs. Check bounceback signal first.
19. High walk rate (BB/9 >3.5) = high-risk for K props — early exit risk kills volume **[T1 for K props; T3 for sizing on other markets]**
20. Always check home/road splits before betting any pitcher's ML or F5 — strong overall ERA can mask dramatically different road profile. Split must be directionally consistent with the bet before logging.
21. Medium-confidence bet cap: max 10 medium bets per session during a losing streak. Total medium exposure capped at $35/session until model restores positive ROI.
22. Before betting any Under or low-total market, check ML line tightness. Lines within 15 cents of pick'em carry meaningful extra-inning risk — **[T2] soft gate — fires one tier downgrade**
23. Do not heavily penalize pitchers returning from IL for first 2–3 starts if pre-IL track record is strong. Regress toward career/prior-season quality faster for established arms — use IL returner regression weights in MODEL_CORE Section 1.
24. If confirmed starter averages <3 IP/start (opener role), pull 1st-inning xERA from Baseball Savant before any F5 or prop analysis. If 1st-inning data unavailable or sample <5 appearances, F5 ML, F5 spread, and all K props are UNQUALIFIED — skip. **[T1]** Full-game ML and totals may still be modeled. Opener on either side = Under suspect on game totals (Rule 31).
25. F5 ML is mandatory for every game with confirmed starters on both sides. Log all F5 plays ≥1.5% edge even when full-game bets exist on the same game. A session output that is missing F5 ML analysis for any game with confirmed starters on both sides is a model failure — flag it explicitly in the session's improvement section. Skipping F5 analysis because no edge is expected is not permitted; the analysis must be run and the result (edge or rejection) must be documented.
26. Run line must be evaluated independently for every game. RL at plus money (+120 or better) with model cover probability >50% is almost always worth logging. The CHC L10 + Taillon xERA 5.20 pattern (PIT RL +178, 4.9% edge) is the canonical example of a missed RL bet.
27. Game total Over is valid even when one team has an elite starter, provided: (a) the opposing starter is high-xERA (>5.5) AND (b) the team facing that starter scores 5.0+ R/G or has rolling 15-game R/G elevated. In this scenario the elite starter suppresses only one half; the other half is wide open. Do not reflexively apply Rule 17 to both halves.
28. When model gap vs Pinnacle vig-free exceeds 10%: flag, note, and if Pinnacle + Kalshi both agree against the model, reduce size by one tier but keep the bet if qualitative case is strong. **[T3]**
29. F5 line verification required before logging F5 bets at Medium/High. Slate carries model F5 probabilities, not actual market prices. Pull actual line on Kalshi. If >20% more expensive than estimated, recalculate edge. **[T1] — Paper only if Kalshi has not posted the line.** (See Rule 42)
30. **[T1] Rule 27 is a hard gate, not a suggestion.** Before logging ANY Under at High confidence, explicitly verify: (a) neither offense is top-5 R/G AND (b) neither opposing starter is xERA >5.5. If either condition fails, Under is BLOCKED at High confidence — downgrade to Medium/Paper or log the Over. Canonical failure: ATL@BOS Under ($8 High, -2.66% CLV, final 13 runs).
31. **[T1] Opener on either side = Under is suspect on game totals.** If either team is using an opener (avg <3 IP/start), flag the game total Under. Opener + top-5 offense = do not log Under regardless of total line.
32. **[T2] Same-game thesis conflict check required.** Before logging a total Under on any game where a ML or F5 is already logged, verify the projected win score is compatible with the Under. If ML thesis requires favored team to score 4–5 runs and total is ≤8.0, the Under margin is dangerously thin — soft gate fires.
33. **[T1] Never buy ML juice above -195 when RL is available at plus money.** When ML is -200 or worse, compare RL CLV first. If RL is plus money with model cover >50%, size the RL and log ML paper only.
34. **[T1] NRFI is blocked when game total is 8.0 or higher** unless BOTH starters have verified sub-3.00 1st-inning xERA (minimum 5-start sample).
35. **[T2] Pull prior-day box score for both offenses before logging any Under.** If either team scored 7+ runs in their last game, require both starters to have 9+ K/9 AND BB/9 <3.0 before logging the Under — otherwise soft gate fires.
36. **[T1] Do not log YRFI based solely on a starter's low K% when their xERA is elite (sub-3.00).** Elite xERA overrides contact-rate YRFI signals. Exception: opposing offense ranks top-5 in 1st-inning run rate. Canonical failure: NYY@KC YRFI — Cole threw shutout with 10Ks.
37. **[T2] Kalshi divergence >15% triggers investigation only when Pinnacle confirms the divergence.** When model and Pinnacle VF agree, Kalshi divergence is noise — do not adjust. When model diverges from BOTH Kalshi and Pinnacle >15%: investigate recent form, injury/lineup news, park, weather, bullpen usage. Only reduce confidence if investigation reveals a specific unmodeled factor. Kalshi is the bet source and edge target. Pinnacle is the sanity check.
38. **Season run differential is not a primary edge input.** Use rolling 15-game R/G and Bounceback/Regression Algorithm (MODEL_CORE Section 9) as primary context. Season run diff = background context only.
39. **[T1] Game total Over on lopsided pitcher matchups belongs in Team Total markets, not game totals.** When an elite offense faces a weak starter (xERA >5.5) but the opposing pitcher is also elite (xFIP <3.00), do NOT log game total Over. Log the elite offense's TT Over or alternate line Overs at plus money. Canonical failure: COL@LAD Total O8 — Ohtani held COL to 1 run.
40. **NRFI/YRFI requires a four-factor composite — do not log based on one or two inputs.** Required: (1) both pitchers' 1st-inning xERA with 5-start sample, (2) both pitchers' recent 1st-inning form last 5 starts, (3) both teams' 1st-inning run rate season and last 15 games, (4) park and lineup factors. Top-5 1st-inning offense = YRFI signal regardless of pitcher. Canonical failure: Brewers NRFI — MIL leads league in 1st-inning runs, this was missed entirely.
41. **[T1] Streak is not a standalone signal and cannot be the primary driver of any bet.** Data: streak across all 9 bets = 3W 6L (33%), -$20.37. Streak-only bets (no other signal): 0W 2L (0%). Streak as primary signal (wt≥0.3): 1W 1L (50%), -$2.36. Streak as confirming signal (wt<0.3): 2W 3L (40%), -$10.01. The signal is negative at every weight level — it adds no value and actively degrades performance when present. **Hard rules: (a) Streak alone is never a reason to log a bet — if streak is the only reason you're looking at a game, skip it. (b) Maximum weight in factors{} is 0.1 — never higher. (c) A bet with streak as the only factor key is a model failure — do not log. (d) Streak does not increase size. (e) Streak does not upgrade confidence tier.** Streak may be noted in the notes field for context (e.g. "team is 7-2 L9") but must not appear in factors{} unless accompanied by at least one data-driven signal (xFIP gap, xERA gap, bullpen vulnerability, bounceback flag). Canonical failures: CHC@PIT ML/TT (+0.5 wt, LOSS/WIN), ATL ML (+0.2 wt, LOSS), MIN@CWS ML (+0.1 wt, LOSS), WSH@CLE ML (+0.3 wt, LOSS). Total streak P/L: -$20.37.
42. **[T1] F5 price verification is a hard pre-log gate.** Before finalizing any F5 bet at Medium or High confidence: (a) pull actual F5 line from Kalshi, (b) recalculate edge using live Kalshi price, (c) if actual price >20% more expensive than estimated, recalculate and downgrade if edge drops below tier threshold. Paper ($1) acceptable if Kalshi has not posted the line.
43. **Use per-tier calibration factors, not flat 0.30.** See MODEL_CORE Section 3 for current factors. Do NOT update factors until N≥50 in each tier. Track signal-type win rates as a higher-frequency leading indicator.
44. **[T1] TT line must be confirmed at logging time for Medium or High confidence bets.** However, TT analysis must be completed regardless of line confirmation status — do not skip the analysis because the line is unknown. Complete the full Poisson projection, calculate the edge, document the analysis, and log at Paper ($1) if the actual TT line cannot be confirmed. "Verify TT line" is not an acceptable note for a Medium or High confidence bet. A TT opportunity must never be silently skipped due to an unconfirmed line.
45. **Apply park factors numerically before comparing projection to line.** Use the numeric table in MODEL_CORE Section 5 — including the GB%/FB% modifier for Coors, GABP, and Dodger Stadium. Do not apply qualitative "hitter-friendly" labels without using the numeric adjustment.
46. **[T1] xERAGap in F5 context is the strongest confirmed signal in the dataset.** 3W 0L across 3 games. Prioritize F5 ML on games with xERA gap ≥1.5 and f5Amplified: true. This is the clearest edge the model has identified.
47. **Bullpen xFIP must be logged with specific tier label.** Use `bullpenVulnerable`, `bullpenElite`, `bullpenFatigued`, or `bullpenAverage` in factors{} — not generic `bullpen: 0.X`. Bullpen is a required input for TT Overs and game totals. Bullpen is explicitly NOT a factor for F5 edge.
48. **xFIP is the primary pitcher input. xERA is secondary context.** All run projections use true_xFIP (regression-blended with season depth, see MODEL_CORE Section 1). xERA may be referenced for narrative context but is never the basis for edge calculation. When xFIP and xERA diverge by >0.5: if xFIP > xERA, pitcher is outperforming true talent — fade; if xFIP < xERA, underperforming — buy. Log both values.
49. **Handedness matchup scalar is required before logging K props AND before finalizing any total or TT projection.** Calculate weighted K% using today's lineup L/R composition vs pitcher's platoon splits. If no split data available (sample <50 PA), note it and do not adjust — do not guess.
50. **[T1] Lineup adjustment factor is required before logging any TT bet at Medium or High confidence.** Compare today's confirmed lineup projected OPS to the team's season OPS baseline. Apply adjustment per MODEL_CORE Section 1 Step 2. If lineup is not yet confirmed, log TT at Paper only.
51. **Projected runs (awayProjRuns, homeProjRuns) must be shown in every game analysis and logged in bets.json.** These are the foundation of all market probabilities. Do not log any bet without first calculating the run projection using the Poisson engine (MODEL_CORE Section 1).
52. **True probability and model% are the same field, derived from Poisson, not from Kalshi.** The Poisson run projection → win probability IS the model%. Kalshi is the comparison point, not the starting point. Do not start from Kalshi and adjust — always start from Poisson.
53. **[T1] CLV must be pulled via web search at settlement — never estimated, never skipped.** At settlement, web search the Pinnacle closing line for each bet. Settle within 48 hours. If no closing line found: log `closingLine: null`, `clv: null`. Never fabricate or estimate.
54. **[NEW — May 28] Compute Poisson probability live, not from table alone.** The lookup tables in MODEL_CORE Section 1 are sanity checks. For any edge calculation within 1% of a tier threshold, or any projection not clearly in the table, compute Poisson directly via bash_tool. Interpolation error at the tier boundary can misclassify a bet.

**IMPORTANT — Kalshi as soft book:** When model agrees with Pinnacle but Kalshi diverges significantly (e.g. Kalshi pricing TOR F5 at -100 while Pinnacle prices -166), this is a KALSHI INEFFICIENCY and the bet should be LOGGED, not blocked. Rule 71 blocks model errors (when Pinnacle disagrees with model). It does not block Kalshi inefficiencies (when Kalshi disagrees with both model and Pinnacle).

**Concrete trigger thresholds — run live Poisson when calculated edge falls in any of these ranges:**
- Paper/Medium boundary: calibrated edge between **1.3% and 1.7%** (±0.2% around 1.5% threshold)
- Medium/High boundary: calibrated edge between **2.8% and 3.2%** (±0.2% around 3.0% threshold)
- f5Amplified lower threshold: calibrated edge between **0.8% and 1.2%** (±0.2% around 1.0% threshold per Rule 69)
- Any projected total between **X.0 and X.5 runs** where X.X is within 0.3 of the market line

**Bash Poisson snippet:**
```python
import math
def poisson_prob(lam, k): return (lam**k * math.exp(-lam)) / math.factorial(k)
def p_over(lam, line): return 1 - sum(poisson_prob(lam, k) for k in range(int(line)+1))
# Example: p_over(4.8, 8.5) → P(team scores 9+)
```

Use signal-type win rates (xERAGap, streak, eliteStarter) as higher-frequency calibration leading indicators. Full factor update only at N≥50.

Pinnacle VF is a sanity check only — it is never the edge target. Market comparison: (1) Model Poisson probability vs Kalshi VF = edge. (2) Model vs Pinnacle VF = sanity check divergence flag. 61. **[T1] Every qualifying bet requires full written analysis — no exceptions regardless of how the bet was surfaced.** Whether a bet surfaces from a headline game deep-dive or a bulk scan, the written analysis must include: (a) **both** starters' true_xFIP calculation shown — not just the starter being faded, (b) offense context for **both** teams (rolling R/G, season R/G, trend direction), (c) specific reason why the line is mispriced and what the market is missing, (d) any gate checks passed or fired, and (e) a qualitative thesis the bettor can read and understand before placing the bet. A bet logged with only numbers and no readable reasoning is a model failure. **The notes field in bets.json must contain a human-readable thesis sentence, not just data.** A notes field that reads only as data points (e.g. "Weathers true_xFIP=3.43. NYY RPG 5.05. Model 62.3% vs VF 56.4%") with no written thesis is a Rule 61 violation — log at Paper only until thesis is written. Canonical failures: (1) May 29 slate — KC/TEX Under, BOS/CLE Under, MIN/PIT Under, SD/WSH ML all logged in bulk scan mode with no written analysis. (2) May 30 NYY@ATH ML -143 (-16.47% CLV, LOSS) — opposing starter J.T. 62. **[T1] Game total Unders at lines ≤8.0 are capped at Medium confidence regardless of calculated edge.** Tight lines leave no margin — one bullpen blowup or crooked inning eliminates the bet. The fragility of a tight Under does not decrease just because the edge calculation looks clean. At lines ≤8.0: High → Medium auto-downgrade. At lines ≤7.5: Medium → Paper auto-downgrade unless both starters have true_xFIP ≤3.50 AND rolling 15-game R/G for both teams is below their season average. Canonical failures: AZ/SEA Under 7 (-$7), CHC/STL Under 7.5 (-$4), LAA/TB Under 8 (-$4), MIN/PIT Under 8 (-$4) — May 29 slate.

63. **[T2] Game total Under requires minimum 1.5-run buffer between run projection and line at High; 1.0-run buffer at Medium.** If `total_proj` is 6.8 and the line is 7.5, buffer is 0.7 — that is Paper only, not Medium. Formula: `buffer = line − total_proj`. Buffer <1.0 → Paper only. Buffer 1.0–1.49 → Medium max. Buffer ≥1.5 → High eligible (subject to all other gates). Log buffer explicitly: `"underBuffer": 1.6`. This is a data-driven gate — buffer must be computed from the actual Poisson projection, not estimated.

64. **[NEW] Three-layer analysis framework required for all Total and Team Total bets.**
  - **Layer 1 — Data anchor:** Rolling 15-game R/G for both teams (pulled from MLB Stats API game logs, not season average). True_xFIP computed from actual last-5-start FIP components where available. Bullpen IP last 3 days per pitcher to flag fatigue. These are hard inputs to the Poisson engine — do not substitute season averages when rolling data is available.
  - **Layer 2 — Qualitative stress test:** One explicit sentence answering: *"What is the single most likely event that blows up this bet, and what is the probability it happens?"* For Unders: name the specific risk (bullpen implosion, crooked inning, starter early exit). For Overs: name the specific risk (starter goes deeper than expected and suppresses the opposing half, bullpen is fresh and elite and locks down a low-scoring game, wind shifts to in, key bat scratched from lineup late). Canonical Over stress-test examples: (a) "Elite opposing starter is on 4-day rest and historically pitches 7+ innings — real risk the Over half is suppressed"; (b) "Home bullpen threw only 3 IP last 3 days — fresh closer could strand a 1-run game"; (c) "Weather shows wind at 12 mph out pregame but forecast calls for shift to crosswind by first pitch." If the risk connects to a data flag (bullpen threw 6 IP yesterday, starter has 85-pitch limit, offense is rolling 5.8 R/G), the qualitative read must reference it. Context adjusts the data — it does not replace it.
  - **Layer 3 — Gate system:** Hard and soft gates apply after Layers 1 and 2. A strong qualitative read does not override a T1 gate. A clean data signal does not bypass the stress test requirement.
  All three layers must appear in the written analysis (per Rule 61). A bet that passes Layer 1 math but has no Layer 2 stress test is incomplete and must be logged Paper only. **[T2 — missing stress test = one tier downgrade]**

65. **[NEW] Rolling 15-game R/G is the primary offense input for Total and TT projections — season R/G is secondary context only.** Pull rolling R/G from MLB Stats API game logs at analysis time. If rolling R/G diverges from season R/G by more than 0.5 runs/game in either direction, flag it explicitly and explain which direction it moves the projection. Do not average the two — use rolling as primary, note season as context. If rolling data is unavailable, use season R/G and note "rolling data unavailable — using season baseline."

76. **[T1] Multiple bets on the same game are permitted only when each bet covers a genuinely independent outcome dimension.** The prohibition is not on quantity — it is on correlated stacking. The test: "If the primary thesis is wrong, how many of these bets lose?" If the answer is all of them, that is one bet logged multiple times, not multiple bets. Required framework: (a) **Correlated cluster (prohibited at full size):** ML + RL + F5 + TT all on the same team all require that team to score runs. One bad pitching performance or cold lineup kills all four simultaneously. These are the same bet. If the model wants all four, pick the single best market and log the rest Paper. (b) **Independent angle stack (permitted):** NRFI + F5 ML + game total + pitcher K prop + ML spans different outcome dimensions. NRFI wins if neither team scores in the 1st regardless of the final. Pitcher K prop wins if the starter misses bats regardless of run support. Game total wins or loses independent of which team wins. These can coexist at real size because they do not all require the same event to occur. (c) **Threshold for multi-bet same game:** the independent angle stack is only warranted when there is a strong, specific reason to believe the market is broadly mispriced on this game — e.g. a pitcher with elite xFIP suppressing a weak lineup AND an offense facing a high walk-rate starter in a low-total environment. The "find" must be documented in notes as the reason for multi-market exposure. If the reason is just "model shows edge on everything," that is a model problem, not a genuine multi-angle opportunity. (d) **Sizing discipline:** when 3+ independent angles are played on the same game, each individual bet must be sized one tier below what it would be in isolation. The aggregate game exposure should not exceed what a single High-confidence bet would cost. Canonical failure: COL@LAA June 1 — LAA ML + LAA RL + LAA F5 + LAA TT + YRFI. All LAA-side scoring bets. COL won 9-8. Every bet lost together. These were not independent angles — they were the same thesis five times.
